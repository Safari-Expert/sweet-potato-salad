# Prepare the Brand Kit and destinations

Use `get_context` to match the connected workspace to the business. Check that each action appears in the connection before using it. An unavailable tool can mean the action has yet to roll out or the connection lacks the corresponding grant. The signed-in CRM sections below provide the fallback.

## Review the business brand

1. Read `get_my_tenant` to compare the current business name, logo, palette and descriptions with the operator’s own site. **Settings → Brand Kit** shows the same branding when only the CRM is available. A workspace name alone cannot establish whether a logo is configured.
2. If branding is missing or differs, offer a preview. Call `preview_website_brand` with the business website. Show the suggested name, wide logo, colors, localized descriptions and social links beside the current values. When there are several logos, let the operator choose. Leave absent provider values out. Check the first invoice address line separately if the operator specifically wants it changed.
3. Obtain explicit approval for the named workspace and the exact changes. Send only those fields with `update_my_tenant`, the verified `workspace_id` and `confirmed: true`. For `long_logo_url` select the Brandfetch CDN logo the operator reviewed. Pass the complete approved palette when replacing colors. Read the saved values back. If the operator declines branding, continue with their current brand. For a custom uploaded logo or an unavailable brand tool, use **Settings → Brand Kit → Quick Load Your Brand** or the Brand Kit upload control. [Approval Gates](approval-gates.md)

## Enable each destination

1. Compare every destination with `list_countries`. Resolve missing countries by name or ISO code with `search_global_countries` and match the result to the itinerary. An enabled country already in the list needs no settings change.
2. Show the workspace name and the missing countries. Once the operator explicitly approves those additions, call `update_my_tenant` with `workspace_id`, `confirmed: true` and `add_country_ids` containing only the approved IDs. Verify with `list_countries`. This enables destinations even for the master-data workspace. Copying master catalog content into the same workspace fails. When these tools are unavailable, guide the operator through the CRM country settings and verify the resulting enabled list before proceeding.
3. Inspect the workspace detail for every itinerary country, including countries already enabled. Use `initialize_destination_detail` with `kind: "country"` and the CRM reference ID when its detail is missing. Use `update_catalog_item` for the opening (`proposal_desc`), main (`main_desc`) and closing (`ending_desc`) descriptions in English and the destination language. In multilingual destinations, choose the language of the tour or ask for the operator’s preference. Preserve existing translations. Apply the [description length check](catalog/master-records.md#descriptions-and-pictures-for-new-items) to each new description.
4. As soon as a country is enabled, fill its three picture slots. Prefer the operator’s website hero for `hero` and two other distinct, representative photos for `main_pictures` and `ending`. Match all three to that country and the operator’s trip. For an existing country, retain suitable saved pictures and fill missing slots. If the site lacks a suitable picture, search for a reusable country-specific image and keep any required attribution.
5. Use `attach_destination_image` with the country ID and the exact slot. Send one JPEG, PNG or WebP as an `image_data` data URI per call, up to 5 MiB decoded. The new image leads the slot and earlier pictures are retained. Read back the country with `get_catalog_item`. Match each returned `file_id` in its intended slot and verify all three slots contain pictures.

## Register and describe major stops

1. Compare the itinerary’s overnights, major visits and transport endpoints with `list_locations` after enabling the countries. Match country, name, aliases and place type. Keep incidental villages in the day narrative unless a service requires them. Treat an airport and its city as distinct places.
2. Tell the operator which significant places are missing. Use `search_location_candidates` with the place and its country. Compare locality, region, type and coordinates. If two plausible matches remain, ask which one the trip means.
3. For the matched candidate, call `register_global_location` with its `place_id` and the expected `country_id`. It registers shared geography and prepares the workspace’s detail. Refresh `list_locations` and use the CRM location ID in the itinerary. For an existing location with missing workspace details, use `initialize_destination_detail` with `kind: "location"` and the CRM location ID.
4. Inspect every location record used in the itinerary, including existing stops and transfer endpoints. Keep accurate saved content. For missing content, use `update_catalog_item` for `main_desc` in English and the trip language and `attach_destination_image` with `kind: "location"`, the location ID and `slot: "main_pictures"`. Search the operator’s itinerary for a picture of that particular place. If none fits, search for a place-specific image licensed for reuse and retain its source and required attribution. Read back the location with `get_catalog_item`. Match the returned `file_id` in `main_pictures` and confirm each new description passes the [length check](catalog/master-records.md#descriptions-and-pictures-for-new-items).
