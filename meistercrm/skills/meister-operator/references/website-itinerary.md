# Recreate a website itinerary as a demo proposal

Use this workflow when a tour operator wants to see one of their published trips in MeisterCRM. The deliverable is a saved Draft for the right lead, with the website's days in order and a verified zero or illustrative quotation. Read [Approval Gates](approval-gates.md) and use the workspace and permissions returned by the current connection.

For the complete workflow, review the actions offered under **Settings → Integrations → MCP**. Brand review (`brand.view`) and saving approved settings (`workspace.manage_settings`) are separate grants. Destination discovery, registration, private detail initialization and images use `geography.view`, `geography.register`, `geography.initialize` and `geography.media`. Draft editing and new template creation use `proposals.edit_draft` and `proposals.create_template` alongside the appropriate lead, proposal and catalog grants. For a step unavailable through MCP, identify the missing action and give the operator the relevant CRM steps.

## Get the trip and map its days

1. Use the exact itinerary URL when supplied. If the operator gives only a homepage, follow a clearly matching named tour and check its title and duration. If several tours or departures fit, ask for the specific trip link. If the itinerary is inaccessible, accept its day-by-day text or brochure and identify any missing days.
2. Read the full itinerary, including expanded day sections. Make a working table with one row per day: day number, stop or route, overnight location, named accommodation, activities, transfers and included extras. Keep trip-wide inclusions once. Preserve free days, optional activities, border crossings and the final departure day. Count overnights separately from travel days.
3. Use the website for itinerary facts and the operator's own media. Record suitable photo sources alongside the matching day and service. Follow [Descriptions and pictures for new items](catalog/master-records.md#descriptions-and-pictures-for-new-items) when creating the catalog entries. Keep an unspecified hotel, flight time, supplier or inclusion clearly identifiable as unspecified. A price advertised on the website is a selling price and provides no evidence of a supplier rate.
4. Resolve the target lead, start date, traveler mix and currency from the request, the [lead](leads.md) and the [proposal defaults](proposals.md). For a new workspace, create a clearly labeled demo lead if requested or included in the onboarding task. Use a synthetic contact with a non-deliverable demo address for that lead and clarify missing trip choices together. Resolve all record IDs from the current workspace. Keep a real customer's lead and traveler roster tied to their own inquiry.

## Prepare the workspace and catalog

1. Follow [Brand Kit, countries and locations](destination-setup.md). Check the existing brand, get approval for workspace-wide changes, enable each missing country, and resolve the major stops. If the user declines branding, continue with the current brand. If a destination remains unavailable, identify the affected days and continue preparing the rest.
2. Match each service against the workspace catalog. Follow [Demo items and rates](catalog/demo-itinerary-items.md) for missing items and rates. Keep a short mapping from each day or global inclusion to its saved master ID, room or rate as applicable, and the intended location. Reuse these IDs when a service appears on several days or work resumes after an interruption.
3. Use zero as the default for a zero-price demo. If the user wants illustrative prices, record the currency, amount and basis (per person, per group, per room or per day) and label the result as a demo. If the choice affects the expected quotation and is unclear, resolve it before pricing.

## Build and save the Draft

1. Check the lead’s proposals for a matching Draft already created for this task. For a new website itinerary, use the [blank Draft procedure](proposals.md) with the actual title, arrival country, start date and day count. Use a template only if the operator selected it as the starting itinerary. Read the saved Draft with `get_proposal`.
2. Prepare the entire ordered set of catalog selections for `set_draft_itinerary`. Give each service its one-based `day`. Use `end_day` when the selected service spans several days. Put a whole-trip add-on once at day zero. Match catalog master IDs, traveler selections, locations and transfer endpoints to the trip. A hotel selection uses the room IDs and meal plan. Omit traveler IDs for the whole party. Keep free days in the proposal duration even if they have no catalog service.
3. Use the Draft’s `proposal_id` and latest `revision` as `expected_revision`. On a populated Draft, show which dated and global services the new plan includes or removes. Replacement recreates every row with a new ID and discards edited item text, manual prices and saved allocations, even for services selected again. Explain these losses before obtaining authorization to set `replace_existing`. A canceled voucher on any row blocks replacement. Open the Draft in the CRM editor to review that row. After a revision conflict or uncertain save, reread the same proposal before taking further action.
4. If an item cannot be priced, use its date and the reported reason to check the rate period, selected room or vehicle, age or party size, and applicable location and currency. Correct the affected selection or demo rate before retrying. A failed calculation or an empty Draft that displays zero does not establish the demo price.

## Verify and optionally create a template

Before handoff, reopen every itinerary country and location by its saved ID. Verify a saved hero, main and closing photo for each country and a place-specific main photo for each location, including reused records. Use the [destination guide](destination-setup.md) to fill missing slots. Complete the [saved-item check](catalog/master-records.md#descriptions-and-pictures-for-new-items) for every new catalog entry. If the task includes checking the customer-facing preview and the requested tools can display it, verify the photos there too. Otherwise report what was verified on the catalog records. Report any outstanding gap by record, slot and reason.

Reopen the saved proposal. Compare the lead, title, dates, day count, stop order, overnights, allocations, activities, transfers and global items against the day table. Check the saved customer total in the quote currency. Report a verified zero or the actual illustrative total. Link to the returned `editor_url` and name any unresolved settings.

If the operator wants a reusable itinerary, call `create_proposal_template` with the verified proposal ID, its latest `expected_revision` and the new `template_name`. Verify its name, country and day count in `list_proposal_templates`. After an uncertain create, look up the name before retrying. A new lead can use the saved template with `create_proposal`, then check allocations and prices for its own party and dates.

If a required tool is unavailable, finish the supported work and give the signed-in CRM editor link, prepared day table, selected items and outstanding actions. Mark a blank or partially populated Draft **quotation pending** until the intended services and price are verified. In the editor, fill the dated timeline and **Global** items, save and check **Quotation**. The optional template action is **Templates → + Create Template**. Customer delivery requires a separate send request.
